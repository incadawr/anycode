## Re-running the live probe

Run `codex-orchestrate-probe.mjs --live --bin PATH --root EMPTY_DIR --auth-from AUTH_JSON` on macOS. An optional `--model` selects a model from `model/list` that supports low effort; otherwise the probe selects an available Luna or mini model. The probe symlinks the supplied auth file into scratch CODEX_HOME and normally runs Codex under a macOS sandbox denying writes to the real auth directory. `ORCH_PROBE_NO_SANDBOX_EXEC=1` disables this guard and requires the caller to enforce the same restriction externally; JSON reports `authWriteGuard` as `external-required`. It seeds two local, read-only MCP fixtures, uses a fresh workspace, and emits a single JSON result with no raw model text, configuration, token or thread ID. The scratch directory itself contains session artifacts and an auth symlink and should be treated as private.

`outcome: completed` means the sequence completed, not that the observed values passed: inspect each result, including marker presence, both sentinel files and whether a write-related tool was observed. Absence of a sentinel without an observed write attempt is inconclusive; the presence of a command or file-change event does not itself prove a write was attempted. `config/read` has no thread ID; MCP status names alone are not proof of callable tool inventory. The OFF marker observation is also limited by prior conversation history. Errors or timeouts produce `outcome: incomplete` and nonzero exit status; the failing step's observations are retained. Token usage/streamed output are monitored and interrupted at the stated limits, but the protocol offers no demonstrated hard output-token cap; the cap is client-side and may be exceeded before a notification arrives. Every RPC and turn has a deadline; teardown terminates the isolated process group.

## Owner-run 0.166.0 live result and alternative candidates

The owner supplied a completed, scrubbed run on 0.166.0 / gpt-6-luna. Same-thread ON/OFF resume was accepted and three completed turn IDs survived `thread/read`. On the loaded thread, the ON marker was absent while the base marker appeared; both fixture MCP tools remained listed after disable overrides. `config/read` also continued to report the ambient config and `multi_agent=true`, but it is process/cwd scoped and does not by itself prove the effective thread settings. Neither sentinel was created; no command or file-change event was observed, so this run does not demonstrate that a write attempt was blocked. Before the first turn, resume was rejected and an ON replacement had a different thread ID. These results supersede the earlier failed-network inference attempt for this version.
