# Codex app-server contract (pinned)

This directory pins the CONSUMED subset of the Codex app-server JSON-RPC
protocol AnyCode's Codex adapter is built against (design
`working-docs/build/design/slice-codex-fixes-cut.md` §2(h)).

- `pinned-contract.json` — canonicalized (sorted keys) extract of exactly the
  methods/types AnyCode's adapter speaks: `initialize`, `account/read`,
  `model/list`, `thread/start|resume|read`, `turn/start|interrupt`,
  `account/login/*`, both approval request/response families
  (command-execution and file-change), the error shape, and the turn-status
  enum. Generated by `apps/desktop/scripts/codex-contract-extract.mjs` from a
  real `codex app-server generate-json-schema --out <dir>` dump.
- `fixtures/*.jsonl` — scrubbed copies of live probe traces (email redacted, home
  path/hostname/installation id replaced; no token/cookie/auth value was ever
  read or stored). Used to build fake-app-server unit tests without asserting
  anything the traces didn't actually show (`contract-drift.test.ts`'s layer-1
  digestion check, plus fixture-driven tests elsewhere in this directory's
  siblings). `w0-*`/`w1-*` are the original W0/W1 probe waves;
  `w2-p1-plan-updated.jsonl` is a later capture (codex-cli 0.144.5, read-only
  sandbox) of two `turn/plan/updated` revisions — the notification family that
  carries Codex's own todo list.
- `contract-drift.test.ts` — the two-layer gate:
  1. **Always-on**: protocol.ts's vocabulary constants and code's reachable
     decision literals stay a subset of the pinned contract;
     `SUPPORTED_CODEX_VERSION` covers the pinned `generatedFrom`; the
     translator digests every fixture line without an unknown-throw.
  2. **Env-gated** (`ANYCODE_CODEX_DRIFT_BIN=<path>`): regenerates the schema
     from a real binary, re-extracts with the same extractor, then holds
     `methods` and `decisionEnums` to byte-equality while checking the shapes as
     a COMPATIBLE SUPERSET — a later in-range binary that only adds optional
     fields passes, a removed definition/property/union-variant fails unless it
     is named in `REVIEWED_REMOVALS`. Deep equality would make any range wider
     than one patch unverifiable by this instrument. Skipped (not failed) when
     the env var is unset.

## Supported version ceiling

`<0.167.0` (mirrors `SUPPORTED_CODEX_VERSION` in
`host/engines/codex/protocol.ts`). TASK.173 (owner decision, 2026-08-29)
dropped the floor this used to pair with: support is a single ceiling, not a
closed range, so any codex-cli build below 0.167.0 is accepted by version
number alone, however old. A build genuinely too old to speak the CONSUMED
wire shapes fails on its own later, at whichever call first needs a shape it
lacks, instead of being preemptively refused here. The Codex CLI's TypeScript
bindings are byte-identical across the observed 0.144.x patch releases; the
generated JSON-schema differs only in property insertion order, which is why
`codex-contract-extract.mjs` canonicalizes by recursively sorting object keys
before comparing.

The pin itself stays on 0.144.x — it is the baseline the adapter was written
and live-smoked against, not a moving target. `0.145.0 .. 0.154.x` was admitted
on the weaker evidence layer 2 now checks: regenerated from the real 0.147.0,
0.149.0, 0.150.1, 0.151.0, 0.152.1, 0.153.4 and 0.154.0 binaries, `methods` and
`decisionEnums` came back byte-identical and no union variant disappeared, and
the handful of removed fields
(`Account.amazonBedrock.credentialSource`, `McpToolCallAppContext.templateId`)
are unconsumed and named in the test's `REVIEWED_REMOVALS`.

0.151.0's own diff against the pin, reviewed for the ceiling raise: `methods`
and `decisionEnums` identical; no definition removed; one added
(`CommandExecutionApprovalKind`, reached through a new optional `kind` on
`CommandExecutionRequestApprovalParams` that defaults to `command`); three
shapes changed, none of them consumed — `CodexErrorInfo` gained
`rateLimitExceeded` and `misalignmentPolicyViolation` and lost NOTHING,
`CommandAction`'s read variant re-pointed `path` at `LegacyAppPathString`, and
`v2.AmazonBedrockCredentialSource` disappeared along with the already-reviewed
field that referenced it. Neither `CommandAction` nor `credentialSource`
appears anywhere in AnyCode's own source. `codex-support.json`
records the two grades separately (`tested` vs `contract-verified`), and
`recommended` deliberately stays on the live-smoked patch: the ceiling says
which Codex a user may bring, `recommended` says which one AnyCode downloads
itself.

0.152.1 / 0.153.4 / 0.154.0's diff against the pin, reviewed for this ceiling
raise (2026-09-11): `methods` and `decisionEnums` byte-identical at all three;
the ONLY shape removals are the three already in `REVIEWED_REMOVALS`, so that
table is unchanged. No enum lost a value. Everything else is additive —
`Model` gained `modelSpecialty`/`multiAgentVersion`, `TurnStartParams` gained
`serviceTierForTurn`/`toolOutput`/`turnTrigger`, `ThreadResumeParams` gained
`excludeTurns`, `InitializeCapabilities` gained `extensions`, `UserInput`
gained `audio`/`localAudio` variants, `InputModality` gained `audio` (the
catalog only asks `includes("image")`), and `CommandExecutionApprovalKind`
settled on `command | writeStdin` (AnyCode reads no `kind` at all and treats
every command-execution approval alike, the posture already accepted at
0.151). One newly REQUIRED field: `Thread.projectId`. `Thread` appears only in
`thread/start|resume|read` RESULTS — no client request carries one — so a
newly-guaranteed field is additive for a reader, not a demand on the sender.

The raise's motivation, recorded because it is not visible in the schema: the
Codex app-server resolves its model list from
`chatgpt.com/backend-api/codex/models?client_version=<version>`, so the
picker's contents are gated by the binary's own version. Measured live on one
account (2026-09-11): 0.144.3 and 0.152.1 offer sol/terra/luna/5.5; 0.153.4
and 0.154.0 additionally offer `gpt-6-astra`.

## 0.160.0 verification (2026-10-03)

The real 0.160.0 binary passes layer 2 and the live GUI smoke **10/10**:
requests, two Allow decisions, Deny verified by disk effects, Stop,
quit/relaunch, exact transcript order on resume, and zero orphan processes.
It is now the recommended installer version. Versions 0.155–0.159 were not
individually live-smoked.

Image input retains `{type:"image", url:"data:..."}`; `url` moved into a
flattened `anyOf` alternative alongside `fileId`. The reviewed-removal entry
is paired with an explicit assertion that the URL alternative still exists.
New Codex persists successful `commandExecution` items in `thread/read`.
Resume therefore retains shadow item IDs, prefers matching native commands,
and anchors shadow-only denied commands in the original native-visible
coordinate space. A live failure exposed this change before the fix; the
subsequent smoke passed without weakening the transcript-order check.

## 0.163.0 / 0.164.0 verification (2026-10-24)

Layer 2 passes against the real 0.163.0 and 0.164.0 binaries; `methods` and

## 0.165.0 verification (2026-10-28)

The real 0.164.0 and 0.165.0 extracted contracts differ only in two

## 0.166.0 verification (2026-10-29)

The real 0.165.0 and 0.166.0 extracts have identical consumed methods and
approval decision enums; no existing fields or variants were removed. The
changes add optional `Account.chatgpt.workspaceName`, `ThreadItem` lifecycle
`startedAtMs` / `completedAtMs`, `imageGeneration.generationId`, and

## Raising the ceiling / updating the pin

Treat this as a single reviewed act, landed in ONE commit:

1. Run `codex app-server generate-json-schema --out <tmpdir>` against the new
   version being admitted (the one the ceiling will be raised to reach).
2. Regenerate, passing the REAL `codex --version` output of that SAME binary
   as the third argument (required, never defaulted — see below):
   ```
   node apps/desktop/scripts/codex-contract-extract.mjs <tmpdir> \
     apps/desktop/src/host/engines/codex/contract/pinned-contract.json \
     "codex-cli 0.144.x"
   ```
   The committed pin deliberately keeps the `0.144.x` RANGE placeholder (not
   a literal patch) — the TS bindings are byte-identical across the observed
   0.144.x patches, so this string documents "any patch in the supported
   range produced this", not one exact probe. `contract-drift.test.ts`'s
   layer 2 passes the exact live `--version` output instead when it
   regenerates for a real-time comparison (see below).
3. Review the diff of `pinned-contract.json` — every consumed method/type that
   changed shape needs an explicit adapter review, not just a green test.
4. Bump `SUPPORTED_CODEX_VERSION` in `host/engines/codex/protocol.ts` to match.
5. Re-run `contract-drift.test.ts` (layer 1 + the always-on hardening suite
   always; layer 2 if a matching binary is available locally) before
   committing.

Extending the CONSUMED vocabulary itself (a new method/type AnyCode starts
speaking) means adding an entry to `codex-contract-extract.mjs`'s
`CLIENT_REQUEST_METHODS` / `SERVER_REQUEST_METHODS` /
`SERVER_NOTIFICATION_METHODS` / `EXTRA_ROOT_REFS` tables (a method name +
result ref only — the params ref is resolved from the live schema's own
`ClientRequest`/`ServerRequest`/`ServerNotification` method registries, see
below), then regenerating — the extractor never infers WHICH methods are
consumed from the schema on its own, but it DOES verify every declared one is
still real.

## Why the extractor can actually detect a renamed method

Earlier versions of this extractor kept a second hardcoded
method-name -> params-type-ref table and trusted it unconditionally — a CLI
release that renamed a consumed method (e.g. `turn/start` -> `turn/begin`)
while leaving `TurnStartParams`'s own shape untouched would still resolve the
old params ref by name and produce a byte-identical pinned contract: a
vacuously green gate. `codex-contract-extract.mjs` now resolves each
consumed method's params ref by MATCHING ITS NAME against the live schema's
own `ClientRequest` / `ServerRequest` / `ServerNotification` definitions —
each a real discriminated union of `{method: {enum:[name]}, params?}`
variants, the actual dispatch table codex-cli's wire protocol uses. A
renamed or removed consumed method throws instead of silently extracting.
`contract-drift.test.ts`'s "hardening" describe block proves this: it
rebuilds a synthetic schema straight from the committed pin (no live binary
needed), confirms the unmutated round-trip still passes, then renames one
method per registry and asserts the extractor throws.


## Taskana 4682 rework — live seatbelt probe protocol (owner-run)

The child temp-dir rework (private `~/.anycode/tmp/<childSessionId>` instead
of losing `/tmp` and `$TMPDIR`) changes three sandbox-relevant things at
once: `excludeTmpdirEnvVar`/`excludeSlashTmp` on every codex child's turn
override (a54b2f6d), the private dir appended to `writableRoots`, and
`TMPDIR`/`TMPPREFIX`/`TMP`/`TEMP` pointing at it in the app-server spawn
env. Only a LIVE seatbelt run proves the composition; a unit fake cannot (it
never applies a profile). Seatbelt cannot nest inside a codex/seatbelt
session — `codex sandbox …` from an already-sandboxed shell fails with
`sandbox-exec: sandbox_apply: Operation not permitted` (reproduced from the
4682 worktree's own Bash, 2026-10-24) — so this protocol is run by the OWNER
from an UNSANDBOXED terminal, once per codex-cli range bump or after any
`workspaceWritePolicy` change.

Step 0 — prepare (scratch workspace repo + the private dir, 0700):

    mkdir -p "$HOME/.anycode/tmp"   # mktemp does not create the template's parent
    WS="$(mktemp -d "$HOME/.anycode/tmp/probe-ws-XXXXXX")/repo"
    mkdir -p "$WS"; git -C "$WS" init -q
    PRIV="$HOME/.anycode/tmp/probe-4682"
    rm -rf "$PRIV" && mkdir -p -m 700 "$PRIV"

The workspace lives OUTSIDE every tmp-family root (under `~/.anycode/tmp`,
but NOT inside `$PRIV` itself, and NOT under `/tmp` or the ambient
`$TMPDIR`): the probe's own policy sets `exclude_tmpdir_env_var=true` and
`exclude_slash_tmp=true`, and a bare `mktemp -d` on macOS resolves under
`/var/folders/.../T` (the ambient TMPDIR) with `/tmp` itself a symlink to
`/private/tmp` — a workspace parked in any of those puts the WRITES THE
PROBE EXPECTS TO SUCCEED (checks 2 and 3 write into `$WS`) inside a path
the exclusions are designed to refuse, so a CORRECT build would fail the
probe. The explicit template above keeps `$WS` home-relative, leaving the
private dir as the ONLY tmp-family path inside the sandbox — exactly what
the probe asserts.

Step 1 — write `probe.sh` next to this README is NOT needed; run the four
checks in ONE child-equivalent invocation. The `-c` overrides mirror
turn/start's sandboxPolicy (workspace-write, the workspace plus the private
dir as writable roots, both tmp exclusions) and the `env` prefix mirrors the
app-server spawn env. (`cd` rather than `codex sandbox -C`: codex-cli
0.164.0 rejects `-C` without `--permission-profile`.)

    cd "$WS" && codex sandbox \
      -c 'sandbox_mode="workspace-write"' \
      -c 'sandbox_workspace_write.writable_roots=["'"$WS"'","'"$PRIV"'"]' \
      -c 'sandbox_workspace_write.exclude_tmpdir_env_var=true' \
      -c 'sandbox_workspace_write.exclude_slash_tmp=true' \
      -- env WS="$WS" TMPDIR="$PRIV" TMP="$PRIV" TEMP="$PRIV" TMPPREFIX="$PRIV/zsh" \
         /bin/zsh -c 'touch /tmp/x'

 replacing the final command with each check below (same prefix):

 1. `touch /tmp/x` — expect REFUSED (the exclusion works; pre-fix this
    silently succeeded — TASK.179's probe).
 2. a zsh heredoc writing a file inside `$WS`
    (`zsh -c 'cat > "$WS/f" <<\EOD ... EOD'`) — expect ok: TMPPREFIX points
    inside the private dir. This is the exact "can't create temp file for
    here document" failure the rework fixes.
 3. `git -C "$WS" add -A && git -C "$WS" -c user.email=p@p -c user.name=p
    commit -m probe` — expect ok (objects land in `$WS/.git`; nothing tmp
    outside the private dir).
 4. `node -e 'require("fs").writeFileSync(require("os").tmpdir()+"/a","1")'`
    — expect ok, with `$PRIV/a` on disk afterwards (`os.tmpdir()` resolved to
    the private dir via TMPDIR).

Then `ls -la "$PRIV"` (expect `a` plus zsh's heredoc scratch files) and clean
up: `rm -rf "$PRIV" "$(dirname "$WS")"`. If any check fails, fix before
shipping — do not weaken the flags to make it pass.

Machine-checked coverage that does NOT need the live run: the child env
family (app-server-client.test.ts), the writableRoots composition
(presets.test.ts, codex-engine.test.ts), the owner-tab byte-identity
(index.test.ts's 4682 shape block), and the dir lifecycle (codex-home.test.ts).
